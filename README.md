# DvigAtel

**DvigAtel** — проект виртуальной производственной сцены для задач видеоаналитики и компьютерного зрения. Решение объединяет **UNIGINE**, **C#**, **Python** и модульную архитектуру для моделирования сцены, обработки видеопотока, детекции объекта контроля и реакции системы на пересечение технологической зоны.

---

## О проекте

Проект создаётся как учебно-прикладная платформа, в которой можно:

- получать **кадры или видеопоток** из виртуальной камеры;
- обрабатывать изображение ML-модулем;
- определять положение объекта относительно **технологической зоны**;
- формировать **события и предупреждения** на основе результата детекции;
- сохранять и визуализировать результаты работы системы.

Решение ориентировано на сценарии, близкие к промышленной видеоаналитике: контроль зоны, отслеживание входа и выхода объекта, журналирование событий и дальнейшее расширение аналитики.

---

## Цель проекта

Собрать единый прототип системы, которая показывает полный цикл работы видеоаналитического решения:

1. виртуальная сцена генерирует наблюдаемый контекст;
2. камера получает изображение;
3. ML-модуль находит объект контроля;
4. интеграционный слой определяет, находится ли объект в технологической зоне;
5. система фиксирует событие и отображает результат.

## Что реализует проект

### Виртуальная сцена

- камера наблюдения в промышленной среде;
- объект контроля;
- технологическая зона;
- сценарии движения объекта:
  - объект вне зоны;
  - вход в зону;
  - движение внутри зоны;
  - выход из зоны.

### ML-модуль

- получение кадров из виртуальной камеры;
- детекция объекта контроля на изображении;
- выдача координат объекта для последующей логики;
- проверка корректности работы на нескольких сценариях сцены.

### Интеграция и событийная логика

- связывание камеры, детектора и системы контроля зоны;
- обработка координат объекта;
- определение его положения относительно зоны;
- генерация событий:
  - объект вне зоны;
  - объект вошёл в зону;
  - объект находится в зоне;
  - объект вышел из зоны;
- сохранение и визуализация результатов:
  - журнал событий;
  - кадры с разметкой;
  - предупреждения о нарушении зоны.

## Архитектура решения

Проект разделён на несколько логических слоёв:

- **Сцена UNIGINE** — отвечает за окружение, камеру и движение объекта.
- **Модуль получения кадров** — передаёт изображение для обработки.
- **ML-модуль** — выполняет детекцию объекта в кадре.
- **Интеграционный модуль** — анализирует координаты и состояние зоны.
- **Модуль событий и хранения** — фиксирует события, результаты и визуальные артефакты.

Такой подход упрощает развитие проекта: можно заменить модель детекции, способ хранения данных или сценарии сцены без полной переработки всей системы.

---

## Сценарии работы

Система корректно обрабатывает несколько ключевых состояний:

- **Объект вне технологической зоны** — базовое состояние наблюдения.
- **Объект входит в зону** — фиксируется переход в область контроля.
- **Объект находится в зоне** — система продолжает отслеживание.
- **Объект выходит из зоны** — фиксируется завершение нарушения или возвращение в безопасное состояние.

---

## Результаты

В текущей версии проекта реализован рабочий прототип полного цикла обработки:

- получение кадров из виртуальной камеры UNIGINE;
- передача изображений в Python-модуль;
- детекция объекта контроля;
- определение положения объекта относительно технологических зон;
- отслеживание состояний `OUTSIDE`, `INSIDE`, `ENTERED`, `EXITED`;
- журналирование событий входа и выхода;
- сохранение текущего состояния зон в `ml_status.json`;
- сохранение размеченных кадров с результатами анализа.

Текущий pipeline:

**UNIGINE → кадр → ML-модуль → координаты объекта → проверка зоны → событие → лог / JSON / визуализация**

Проект поддерживает одновременный контроль нескольких технологических зон и формирует события только при изменении их состояния.
